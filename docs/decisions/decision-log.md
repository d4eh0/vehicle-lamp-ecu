## D-03 — 시동과 미등의 관계

- **결정일시:** 2026-10-28 12:56 KST (최초 GitHub 기록 커밋 시각 기준)

- **상태:** 확정 (사용자 선택: B)
- **문제:** 시동 상태와 미등 제어를 연동할지, 별도의 조명 제어 입력을 둘지 정해야 한다.
- **선택:** 시동 입력과 별도의 미등 스위치를 두어 미등 ON/OFF를 독립적으로 제어한다. 조도센서 기반 AUTO 모드는 이번 범위에서 제외한다.
- **대안:** (A) 시동 ON에 미등 자동 연동, (C) 조도센서 기반 AUTO 모드.
- **선택 근거:** 실제 차량의 조명 스위치 개념과 유사한 입력을 모델링할 수 있고, 시동과 미등 입력의 조합을 독립적인 SYS/SWE 요구사항과 SIL/HIL 시나리오로 검증할 수 있다.
- **트레이드오프:** 별도 스위치·입력 채널이 추가된다. 조도 기반 자동 제어는 구현하지 않는다.
- **검증 방향(아직 테스트 미수행):** 시동/미등 스위치의 입력 조합에 대해 정의된 미등 출력 정책을 시험한다.
- **미결 사항:** 시동 OFF일 때 미등 스위치가 ON이면 실제 점등을 허용할지는 D-06에서 확정한다. 입력 스위치의 세부 전기적 구현은 SYS.3에서 확정한다.

## D-04 — 조작 입력 방식

- **결정일시:** 2026-10-28 12:58 KST (최초 GitHub 기록 커밋 시각 기준)

- **상태:** 확정 (사용자 선택)
- **문제:** 3단 레버와 각 버튼의 물리 조작을 차량 램프 제어 명령에 어떻게 매핑할지 정의한다.
- **결정 1 — 방향지시 레버:** 위=우회전, 중앙=OFF, 아래=좌회전. 레버 위치가 유지되는 3단 입력으로 모델링한다.
- **결정 2 — 브레이크:** 버튼을 누르고 있는 동안만 제동 요청을 활성화하며, 놓으면 해제한다.
- **결정 3 — 비상등:** 버튼을 누를 때마다 비상등 상태가 ON/OFF 전환되는 토글 동작을 채택한다.
- **선택 근거:** 레버 위치, 제동 페달의 지속 입력, 비상등의 토글 조작을 분리해 현실적인 입력 상태와 재현 가능한 SIL/HIL 시험 시나리오를 확보한다.
- **대안과 트레이드오프:** 방향 레버의 위/아래를 반대로 매핑할 수 있으나 일반적인 차량 조작에 맞춘 방향을 선택했다. 브레이크·비상등을 모두 단순 토글 또는 눌림 유지 방식으로 처리하는 대안은 실제 조작 특성과 맞지 않아 제외했다. 비상등 토글은 접점 바운스로 인한 중복 전환 위험이 있다.
- **검증 방향(미수행):** 레버의 3개 고정 위치, 브레이크 누름/해제, 비상등 연속 누름의 입력-상태 변화를 SIL 및 HIL에서 확인한다.
- **추가 결정 대기열:** D-09 — 디바운싱 적용 범위·방식·시간 및 버튼 1회 누름 판정.
- **별도 후속 결정:** 비상등·방향지시등 충돌 시 우선순위는 D-05에서, 시동 OFF 동작은 D-06에서 정한다.

## D-05 — 동시 작동 및 출력 우선순위

- **결정일시:** 2026-10-28 16:44 KST (최초 GitHub 기록 커밋 시각 기준)

- **상태:** 확정 (사용자 선택)
- **문제:** 복수 명령이 동시에 활성화될 때 램프 간 출력 충돌과 우선순위를 정해야 한다.
- **결정 1 — 비상등 우선:** 비상등이 활성화되면 좌·우 방향지시등을 동시에 점멸시킨다. 비상등 활성 중 방향지시 레버의 출력 명령보다 비상등 명령이 우선한다.
- **결정 2 — 후방 미등/제동등 공용 LED:** 두 기능은 동일한 LED 출력 채널을 공유하고 PWM으로 밝기를 구별한다. 미등만 켜질 때는 낮은 밝기, 브레이크 입력이 있으면 미등 입력과 무관하게 높은 밝기로 작동한다. 브레이크 해제 후 미등 입력이 남아 있으면 미등 밝기로 복귀한다.
- **결정 3 — 후진등 독립:** R 입력에 따른 후진등은 방향지시등·비상등·미등·제동등과 서로 배타적이지 않으며 동시 작동할 수 있다.
- **선택 근거:** 비상등의 명확한 명령 우선순위, 실제 후방 램프의 미등/제동 겸용 원리, 독립 후진등 동작을 모사한다. 우선순위 충돌과 공용 출력의 복수 입력 조합을 SIL/HIL로 검증할 수 있다.
- **검토한 대안:** 방향지시등 우선 또는 마지막 입력 우선, 미등/제동등을 별도 LED로 분리, 후진 중 타 램프 기능 제한.
- **트레이드오프:** 공용 LED 밝기 제어에는 PWM 구현 및 듀티·주파수·눈에 보이는 밝기 차이 검증이 필요하다. 서로 독립된 기능을 공유 출력에 매핑하므로 미등·제동등 출력 진리표를 명확하게 정의해야 한다.
- **검증 방향(아직 테스트 미수행):** 비상등/방향지시 동시 입력 시 좌우 동기 점멸 확인; 미등·제동 입력 4조합의 공용 LED 출력 단계 확인; R과 타 기능을 동시에 활성화한 상태에서 후진등 출력 확인.
- **미결 사항 및 대기열:** D-10 보조제동등(CHMSL) 중앙 LED 3개 추가 여부; D-11 PWM 밝기·주파수·듀티 및 수용 기준. 둘 다 D-08 완료 후 결정한다. 점멸 타이밍/상태 전환은 D-07에서 결정한다.

## D-06 — 시동 OFF 시 램프 동작 정책

- **결정일시:** 2026-10-28 16:46 KST (최초 GitHub 기록 커밋 시각 기준)

- **상태:** 확정 (사용자 선택: A — 차량 동작 유사형)
- **문제:** 시동이 OFF여도 경고·차량 위치·제동 관련 램프가 필요할 수 있으므로 기능별 입력 처리와 출력 허용 여부를 정의한다.
- **결정:** 시동 OFF 상태에서 비상등, 미등, 제동등은 해당 입력 조건이 충족되면 작동을 허용한다. 방향지시등과 후진등은 명령이 입력되어도 출력을 비활성화한다.
- **동작표:** 비상등=허용 / 미등=허용 / 제동등=허용 / 방향지시등=차단 / 후진등=차단. 허용은 항상 점등한다는 의미가 아니다.
- **기존 결정과의 관계:** D-03의 별도 미등 스위치 정책을 유지한다. D-05의 비상등 우선 및 공용 미등·제동등 PWM 제어도 유지하되, 시동 OFF의 출력 허용 조건을 먼저 적용한다.
- **선택 근거:** 주차 중 비상등·미등 사용 및 시동 정지 상태에서의 브레이크 입력을 모사하고, 시동 상태에 따른 출력 제한을 요구사항과 SIL/HIL 테스트로 검증할 수 있다.
- **검토 대안:** 비상등만 허용, 모든 램프를 시동과 무관하게 허용.
- **트레이드오프:** 시동 OFF 시에도 실제 ECU가 작동할 전원 구조가 필요하며, 시동 전환 직후 입력 및 토글 상태를 어떻게 처리하는지 별도 정의해야 한다.
- **검증 방향(미수행):** 시동 OFF에서 기능별 유효 입력을 주고 허용된 세 램프만 동작하는지 검증한다. 방향지시 레버와 R 입력이 들어와도 해당 출력은 차단되는지 확인한다.
- **추가 결정 대기열:** D-12 — 시동 OFF/ON 전환 시 유지 중인 입력 재평가, 토글 상태 보존/초기화, 시동 OFF 전원 공급 조건. D-08 이후 결정하고 세부 전원 구조는 SYS.3에서 설계한다.

## D-07 — 방향지시등·비상등 점멸 및 위상 정책

- **결정일시:** 2026-10-28 16:48 KST (최초 GitHub 기록 커밋 시각 기준)

- **상태:** 확정 (사용자 선택: B / B / A)
- **문제:** 점멸 간격·타이밍 품질과 좌/우 방향지시등 및 비상등 간 전환 시 위상을 일관되게 정의해야 한다.
- **결정 1 — 주기:** 점멸 기능 활성화 시 출력 ON 400 ms, 이어서 OFF 400 ms를 반복한다(완전한 점멸 주기 800 ms, 분당 75회, ON/OFF 비율 50%).
- **결정 2 — 허용 오차:** 정상 연속 점멸 시 각 ON 및 OFF 구간의 실제 길이는 목표 400 ms 대비 ±20 ms(380~420 ms)를 합격 기준으로 한다.
- **결정 3 — 기능 전환:** 좌/우 방향지시등 및 비상등 등 활성 점멸 기능이 다른 점멸 기능으로 변경되는 시점에는 기존 타이밍 상태를 버리고 새 기능을 ON 상태로 시작하며 점멸 타이머를 초기화한다. 비상등 우선순위는 D-05를 따른다.
- **대안:** 500 ms ON/OFF(60회/분), 300 ms ON/OFF(100회/분); 오차 ±10 ms 또는 ±50 ms; 이전 위상을 유지하는 방식.
- **선택 근거:** 400/400 ms는 육안으로 확인 가능한 규칙적 점멸을 만들고, 기능 전환 시 ON부터 재시작하면 좌우 출력 동기화와 SIL/HIL 기대 결과를 명확히 정의할 수 있다. ±20 ms는 프로젝트에서 정한 정량적인 검증 기준이다.
- **트레이드오프:** 위상 리셋은 전환 순간 ON/OFF 구간 길이를 끊을 수 있다. 따라서 전환 중 잘린 구간과 안정적인 연속 점멸 구간을 검증 시 구분해야 한다. 실제 MCU 스케줄링·GPIO 출력 측정을 통해 ±20 ms 충족 여부를 확인해야 한다.
- **검증 방향(아직 테스트 미수행):** SIL로 380/400/420 ms 경계 조건과 상태 전환 시 타이머 리셋을 검증하고, HIL에서 STM32 실제 GPIO ON/OFF 구간을 측정한다. 비상등 활성 시 좌/우 동기화도 확인한다.
- **미결 사항 및 대기열:** D-13 — 점멸 요청 인식에서 최초 ON까지 허용할 응답 지연 및 SIL/HIL 측정 시작 시점. 이는 연속 점멸 ON/OFF 허용 오차와 별도이다.
- **참고:** 400/400 ms 점멸 타이밍과 미등/제동등 PWM 캐리어 주파수(D-11)는 서로 다른 개념이다.

## D-08 — 초기화·비정상 입력·고장 주입 범위

- **결정일시:** 2026-10-28 16:52 KST (최초 GitHub 기록 커밋 시각 기준)

- **상태:** 확정 (사용자 선택: A / A / B)
- **문제:** MCU 재부팅, 물리적으로 불가능한 레버 신호, 제어 출력 관련 오류 시 ECU가 예측 가능한 동작을 해야 한다.
- **결정 1 — 재부팅:** 초기화 중에는 램프 출력을 OFF로 두고, 초기화가 끝나면 현재 물리 스위치 상태를 재평가해 적용한다. 소프트웨어 토글 상태인 비상등은 재부팅 시 OFF로 초기화한다.
- **결정 2 — 유효하지 않은 방향 레버 입력:** 좌·우 방향지시 입력이 동시에 활성화되면 방향지시 요청을 무효로 하고 오류를 기록한다. 비상등 및 다른 정상 램프 기능은 계속 동작한다. D-05 비상등 우선 정책을 그대로 적용한다.
- **결정 3 — 고장 검증 범위:** 비정상 입력을 SIL/Custom HIL로 시험하고, 테스트 전용 인터페이스를 통해 가상 출력 고장을 주입하여 진단·대응 로직을 검증한다. **실제 LED 단선·단락을 감지하는 회로를 구현하기로 한 결정은 아니다.**
- **선택 근거:** 초기 상태를 명확히 정의하고 오동작 명령을 차단하여 정상 기능에 영향을 최소화하며, HW 검출 회로 없이도 가상 고장으로 SW 오류 경로를 재현·검증할 수 있다.
- **검토 대안:** 재부팅 전 상태를 비휘발성 메모리로 복구; 비정상 레버 입력 시 마지막 정상 레버 상태 유지; 실제 전압/전류 피드백 회로에 기반한 출력 고장 검출.
- **트레이드오프:** 초기화 중 출력 OFF로 인한 일시적인 소등 구간이 있으며, 리셋 이전 비상등 ON 상태도 보존되지 않는다. 가상 출력 고장 테스트가 실제 고장 탐지 능력을 입증하지는 않는다.
- **검증 방향(미수행):** 현재 미등·브레이크·레버 입력을 유지한 채 리셋하여 초기화 후 재평가되는지 검증한다. 비상등 ON 뒤 리셋 시 OFF 초기화 여부를 검증한다. 좌/우 동시 레버 입력으로 방향지시 출력이 무효화되고 오류가 기록되는지, 동시에 비상등·미등·제동등 등 정상 기능이 유지되는지 확인한다. 테스트용 가상 출력 고장 주입 시 지정한 오류 처리가 발생하는지 검증한다.
- **추가 대기열:** D-14 — 가상 출력 고장의 주입 방식, 고장 발생 시 출력별 안전 대응, 고장 해제 조건 및 로그의 내용·유지 정책. 추후 상세 제어 정책을 정한다.

## D-10 — 중앙 보조제동등(CHMSL) 구성

- **결정일시:** 2026-10-28 19:57 KST (최초 GitHub 기록 커밋 시각 기준; 사용자 선택의 정확한 시각과는 다를 수 있음)
- **상태:** 확정 (A안 — 독립 GPIO 출력 채널)
- **결정:** 후면 중앙에 적색 LED 3개를 배치하고, STM32의 별도 GPIO 출력 채널 1개가 이 LED 3개를 하나의 보조제동등으로 제어한다. 브레이크 입력이 유효할 때만 중앙 보조제동등이 점등하며, 미등 입력만 ON이면 중앙 보조제동등은 OFF이다.
- **기존 정책과의 관계:** D-05의 좌우 공용 미등·제동등 PWM 출력과 분리한다. D-06에 따라 시동 OFF에서도 브레이크 입력에 반응한다. D-08의 재부팅 초기화 동안에는 OFF로 두고 현재 유효 입력을 재평가한다.
- **선택 근거:** ECU SW가 중앙 보조제동등을 개별 출력으로 명령·검증할 수 있어 제동등 간 기능 분리, 상태 추적 및 SIL/HIL 출력 검증이 명확하다.
- **대안:** 브레이크 입력을 외부 구동 회로로 직접 분기하여 중앙 LED를 구동하는 방식, 중앙 보조제동등을 제외하는 방식.
- **트레이드오프 및 한계:** STM32 GPIO와 LED 구동 회로·배선이 추가된다. MCU가 고장 나거나 리셋되면 중앙 제동등이 동작하지 않을 수 있으므로 실제 양산 안전성을 확보한 설계로 주장하지 않는다. 테스트용 가상 출력 고장 주입은 실제 LED 단선 감지를 뜻하지 않는다.
- **시스템 아키텍처 후속 설계(SYS.3):** LED 3개 각각의 전류 제한 저항, 총 소비 전류에 적합한 트랜지스터/드라이버, GPIO 핀 배정 및 구동 전압을 결정한다. GPIO에 LED 3개를 무조건 직접 병렬 연결하지 않는다.
- **검증 방향(아직 미수행):** 브레이크 ON/OFF, 미등만 ON, 미등과 브레이크 동시 ON, 시동 OFF 상태의 브레이크 입력, MCU 초기화 시 중앙 출력의 상태를 SIL/HIL에서 검증한다. 다른 제동 출력과 별도 GPIO 관측으로 출력 채널 독립성을 확인한다.

## D-11 — 공용 미등·제동등 LED PWM 제어 정책

- **결정일시:** 2026-10-28 20:00 KST (최초 GitHub 기록 커밋 시각 기준)
- **상태:** 확정 (사용자 선택: A / B / A)
- **문제:** 공용 LED 출력의 미등/제동 상태별 구동 명령과 PWM 검증의 정량 기준을 정해야 한다.
- **결정 1 — 출력 단계:** 미등 OFF·브레이크 OFF는 0% (OFF). 미등 ON·브레이크 OFF는 PWM 듀티 20%. 브레이크 ON이면 미등 입력과 무관하게 연속 ON (100%)으로 제동 밝기를 우선한다.
- **결정 2 — PWM 주파수:** 미등 모드의 PWM 주파수는 1,000Hz (주기 1ms). 제동 모드 100%는 연속 HIGH 출력이며 PWM 스위칭 파형 검증 대상에서 제외한다.
- **결정 3 — HIL 허용 오차:** 미등 PWM의 듀티비는 목표 20% 대비 ±2%p (18~22%), 주파수는 목표 1,000Hz 대비 ±5% (950~1,050Hz)를 초기 합격 범위로 한다.
- **선택 근거:** 공용 LED에서 미등과 제동을 명확히 구분하고 STM32 하드웨어 타이머를 통한 제어·SIL 및 HIL 검증 지표를 확보한다.
- **대안:** 미등 30% 또는 40%; PWM 500Hz 또는 2kHz; 완화된 허용 오차 ±5%p/±10%.
- **트레이드오프 및 한계:** 듀티비 20%가 실제 광속의 20%를 뜻하지 않으며 육안 밝기와 카메라 촬영 결과도 비선형이다. 출력 파형 검증과 광학적 밝기 검증은 구분한다. UNO Q를 이용한 1kHz PWM 측정 가능성과 구체적인 측정법은 SYS.3/SYS.4 단계에서 검증해야 한다.
- **검증 방향(미수행):** 미등/제동 입력 4가지 조합에서 OFF/20%/100%를 검증하고 브레이크 누름 및 해제 후 우선순위·복귀를 확인한다. 실물 GPIO 파형의 PWM 주파수·듀티 및 허용 오차를 측정한다.

## D-12 — 시동 전환·MCU 전원 공급 정책

- **결정일시:** 2026-10-28 20:03 KST (최초 GitHub 기록 커밋 시각 기준)
- **상태:** 확정 (사용자 선택: A / A / A)
- **문제:** IGN OFF/ON 전환 시 토글 상태·유지형 스위치 상태를 처리하고, IGN OFF에도 작동해야 하는 램프 기능의 MCU 전원 조건을 정한다.
- **결정 1 — 비상등 상태 유지:** MCU가 계속 동작하는 동안 IGN OFF/ON 전환은 비상등 소프트웨어 토글 ON/OFF 상태를 변경하지 않는다. 실제 MCU 재부팅 시에는 D-08에 따라 비상등 토글을 OFF로 초기화한다.
- **결정 2 — 현재 입력 반영:** IGN이 OFF에서 ON으로 전환되면 현재 디바운싱을 통과한 방향지시 레버와 후진 R 입력을 즉시 재평가하여 적용한다. 비상등 활성 시 방향지시등보다 우선하는 정책은 D-05를 따르며, 새로운 점멸 모드 시작 시 D-07 타이밍 정책을 따른다.
- **결정 3 — ECU 전원:** IGN 상태는 MCU의 논리 입력이며, IGN OFF 상태에서도 STM32에는 계속 전원을 공급한다. 전원 공급 중단은 별도 MCU 리셋/전원 상실 이벤트다.
- **선택 근거:** D-06의 시동 OFF 비상등·미등·제동등 허용 조건을 만족시키고, IGN 변경과 MCU 부팅을 구분하여 시스템 상태머신과 SIL/HIL 시험 조건을 단순하고 명확하게 설계한다.
- **대안:** 시동 OFF 시 비상등 토글 리셋, IGN ON 후 스위치를 재조작해야 기능 활성화, IGN OFF 시 MCU 저전력 모드로 전환.
- **트레이드오프:** 시동 OFF에도 MCU를 계속 가동하므로 실제 배터리 기반 ECU라면 대기전류 관리가 필요하다. 이 프로젝트는 전원과 시동 입력을 분리하는 시제품 모델이며 실차 저전력·전원 안전성 요구사항을 충족한다고 주장하지 않는다.
- **검증 방향(미수행):** 비상등 ON인 상태로 IGN을 OFF/ON 전환하여 토글 유지 확인; 시동 OFF에서 레버/후진을 활성화해 출력 차단 확인 후 IGN ON에서 즉시 출력 발생 확인; IGN OFF에서도 미등·제동·비상등 기능이 동작하는지 검증; MCU 재부팅 시 D-08 초기화와 구별 검증.
- **SYS.3 후속 설계:** 외부 전원·IGN 입력 분리, 논리 레벨 및 3.3V 입력 보호, MCU 상시 전원 시제품 배선 및 필요 시 전류 측정.
