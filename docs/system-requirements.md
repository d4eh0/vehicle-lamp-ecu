# SYS.2 — 시스템 요구사항 (초안)

> SYS.1의 STK 요구사항을 시험 가능한 시스템 동작으로 구체화하는 단계. **현재 검토 중**이며 하드웨어 구현·시험은 시작 전이다.

## 1. 시스템 경계

- **BCM 시뮬레이터:** UNO Q가 6종 물리 입력을 처리하고 Classical CAN으로 램프 명령을 전송한다.
- **후방 램프 ECU:** STM32F103이 유효한 CAN 명령을 수신해 TURN_L, TURN_R, TAIL_STOP_L, TAIL_STOP_R, REVERSE_LAMP, CHMSL의 6개 논리 채널을 제어한다.
- **검증:** PC SIL과 UNO Q 기반 Custom HIL. UNO Q의 CAN 송신 및 실제 출력 계측 방식은 SYS.3에서 결정한다.
- **확장:** CAN FD는 별도 하드웨어 구성이 필요한 후속 과제이다.

## 2. 시스템 요구사항

각 항목은 SYS.1의 STK 요구사항에 연결한다. 아래 수치와 시험 조건은 **초안이며 SYS.2 검토 후 확정**한다.

### 2.1 방향지시등·비상등

| ID | 요구사항 초안 | 상위 요구 |
|---|---|---|
| SYS-001 | IGN ON·비상등 OFF에서 우측 명령은 TURN_R, 좌측 명령은 TURN_L만 점멸하고 OFF 명령에서는 양쪽이 OFF여야 한다. | STK-002, STK-008 |
| SYS-002 | UNO Q는 비상등 버튼의 유효한 눌림 한 번에 비상등 상태를 한 번 변경하고 CAN으로 상태를 전달해야 한다. 길게 눌러도 중복 토글하지 않는다. | STK-003, STK-014 |
| SYS-003 | 비상등 ON 시 IGN·방향 레버와 무관하게 TURN_L/R이 같은 위상으로 점멸하며 일반 방향지시 요청보다 우선해야 한다. | STK-003, STK-008 |
| SYS-004 | 안정적인 점멸 구간의 ON·OFF 길이는 각각 400±20ms여야 한다. 기능 전환 시 잘린 구간은 측정에서 제외한다. | STK-004 |
| SYS-005 | 활성 점멸 기능이 변경되면 새 기능을 ON부터 시작하고 점멸 타이머를 초기화해야 한다. | STK-004 |
| SYS-006 | 방향 레버 물리 입력에서 첫 ECU 출력 ON까지의 종단간 응답시간을 만족해야 한다. **수치·측정 시작점 확정 필요.** | STK-002, STK-016 |
| SYS-007 | 비상등 버튼 물리 입력에서 좌우 첫 출력 ON까지 종단간 응답시간을 만족해야 한다. **수치·측정 시작점 확정 필요.** | STK-003, STK-016 |

### 2.2 미등·제동등·후진등

| ID | 요구사항 초안 | 상위 요구 |
|---|---|---|
| SYS-008 | 미등·브레이크 명령의 4개 조합에서 좌우 공용 램프와 CHMSL은 아래 진리표를 따라야 한다. | STK-005, STK-006 |
| SYS-009 | 미등만 ON이면 좌우 공용 출력은 PWM 듀티 18~22%, 주파수 950~1050Hz여야 한다. 브레이크 ON은 연속 ON이다. | STK-005 |
| SYS-010 | IGN ON이고 후진 명령이 R이면 REVERSE_LAMP가 ON, NOT R이면 OFF여야 한다. 다른 허용된 기능과 함께 동작 가능해야 한다. | STK-007 |
| SYS-011 | IGN OFF에서는 일반 방향지시·후진등을 차단하고 비상등·미등·제동등·CHMSL은 유효 명령에 따라 허용해야 한다. | STK-008 |

**좌우 공용 미등·제동등 진리표** (정상 명령, 가상 고장 없음)

| 미등 | 브레이크 | TAIL_STOP_L/R | CHMSL |
|---|---|---|---|
| OFF | OFF | OFF (0%) | OFF |
| ON | OFF | PWM 20%, 1kHz | OFF |
| OFF | ON | 연속 ON (100%) | ON |
| ON | ON | 연속 ON (100%) | ON |

### 2.3 시동·초기화·비정상 명령

| ID | 요구사항 초안 | 상위 요구 |
|---|---|---|
| SYS-012 | 전원이 유지되는 동안 IGN OFF/ON만으로 UNO Q의 비상등 토글 상태가 변해서는 안 된다. | STK-009 |
| SYS-013 | IGN OFF→ON 시 이미 유지 중인 방향 레버·후진 상태를 추가 조작 없이 CAN으로 전달하고 출력에 반영해야 한다. | STK-009 |
| SYS-014 | IGN OFF 상태에도 ECU의 전원이 유지되어 허용된 램프 요청을 처리해야 한다. | STK-015 |
| SYS-015 | ECU 초기화 중 모든 램프 출력은 OFF여야 하며, 초기화 이후 새로 수신한 유효 CAN 상태를 반영해야 한다. **BCM 비상등 상태 동기화 규칙은 추가 확정 필요.** | STK-010 |
| SYS-016 | 좌·우 동시 활성 등 유효하지 않은 방향 명령을 수신하면 일반 방향지시를 비활성화하고 오류 이벤트를 기록해야 한다. 다른 정상 기능은 유지해야 한다. | STK-011 |

### 2.4 시험용 가상 출력 고장

| ID | 요구사항 초안 | 상위 요구 |
|---|---|---|
| SYS-017 | 시험 빌드에서 별도 UART 명령으로 채널별 가상 고장을 설정·해제할 수 있어야 한다. PC SIL에서는 동일 로직을 내부 API로 호출한다. | STK-012 |
| SYS-018 | 가상 고장이 지정된 출력 채널만 강제 OFF하며 정상 채널은 제어 규칙을 유지해야 한다. | STK-012 |
| SYS-019 | 가상 고장은 명시적 CLEAR까지 유지하고 해제 시 최신 유효 명령에 맞게 출력을 복구해야 한다. | STK-012 |
| SYS-020 | 오류 이벤트(코드·채널·발생/해제·시간)를 RAM에 최근 16건 기록하고 초과 시 가장 오래된 이력을 덮어써야 한다. MCU 리셋 시 RAM 이력·가상 고장 상태는 초기화된다. | STK-012 |

### 2.5 CAN 인터페이스

| ID | 요구사항 초안 | 상위 요구 |
|---|---|---|
| SYS-021 | UNO Q는 안정화된 조작 상태와 비상등 토글을 Classical CAN 명령으로 STM32 ECU에 전달해야 한다. | STK-001, STK-014 |
| SYS-022 | STM32 ECU는 수신 CAN 데이터의 유효성을 검사하고 유효한 명령을 램프 제어 로직에 반영해야 한다. | STK-001, STK-013 |
| SYS-023 | ECU는 CAN 메시지 누락·잘못된 값·장시간 무수신을 판별하고 정해진 정책대로 처리해야 한다. **타임아웃과 채널별 출력 정책 확정 필요.** | STK-013 |

## 3. SWE.1에 반영할 소프트웨어 요구 후보

| 내용 | 담당 |
|---|---|
| 비상등·IGN 20ms, 레버·미등·후진 10ms, 브레이크 5ms 디바운싱 | BCM 시뮬레이터(UNO Q) |
| 비상등 버튼 눌림 1회·해제 확인 후 재입력 | BCM 시뮬레이터(UNO Q) |
| CAN 수신·데이터 유효성·최신 상태 적용 및 타임아웃 감지 | 후방 램프 ECU(STM32) |
| 점멸 상태머신, 위상 초기화, PWM 출력, 고장 격리, 로그 | 후방 램프 ECU(STM32) |

## 4. SYS.2 검토·확정 항목

- [ ] CAN 메시지 ID, 데이터 필드, 주기, 정상/비정상 값 정의
- [ ] BCM 상태 보존 및 ECU 리셋 후 재동기화
- [ ] 통신 끊김 시 비상등·제동등·미등 등 채널별 동작 정책
- [ ] 방향지시·비상등 E2E 응답시간 목표와 계측 조건 (기존 직접입력 20/30ms는 사용하지 않음)
- [ ] SYS-001~023 상충·누락·시험 가능성 검토
- [ ] 승인된 요구사항과 검증 계획 연결

요구사항 검토가 완료되기 전에는 SYS.2를 완료로 표시하지 않는다.
