# SYS.1 — 후방 램프 ECU 요구사항

## 1. 무엇을 개발할 것인가?

### 1.1 개발 대상

차량 후방 조명 기능을 제어하는 **Rear Lamp ECU 프로토타입**을 개발한다. 램프 기능을 BCM에서 직접 구동하는 대신, BCM과 별도 후방 램프 ECU 간에 명령을 주고받는 **분산형 제어 구조**를 선택했다.

| 검토 항목 | 선택한 방향 | 제외한 방향 및 이유 |
|---|---|---|
| 램프 범위 | 후방 램프 집중 | 전방 램프까지 포함하면 출력·회로·시험 범위 증가 |
| 제어 구조 | BCM → CAN → 후방 램프 ECU → LED | BCM에서 드라이버를 직접 제어하는 구조 대신 ECU 간 통신·제어 SW 구현 |
| 통신 1차 구현 | Classical CAN | LIN은 이번 범위에서 제외 |
| 통신 확장 | CAN FD 구현 가능성 검토 | 현재 STM32F103 내장 CAN으로는 CAN FD 불가 |

### 1.2 시스템 구성과 책임

    물리 스위치 → Arduino UNO Q (BCM 시뮬레이터)
                                    │ Classical CAN
                                    ▼
                         STM32F103C8T6 (Rear Lamp ECU)
                                    │ GPIO / PWM
                                    ▼
                           LED 구동회로 → 후방 LED

| 구성 요소 | 담당 기능 |
|---|---|
| Arduino UNO Q | 운전자 조작 입력, 스위치 안정화, BCM의 램프 명령 송신 모사 |
| CAN 네트워크 | UNO Q와 ECU 간 램프 제어 정보 전달 |
| STM32F103C8T6 | CAN 명령 수신, 기능 우선순위, 점멸, PWM, 출력 및 진단 |
| LED 구동회로 | MCU 신호에 따라 실제 LED 전류 제어 |
| PC / HIL | 제어 로직과 실제 입출력 검증 |

BCM 시뮬레이터는 실제 차체 제어 기능 전체를 구현하지 않고 **후방 조명에 필요한 명령만 모사**한다. MCU는 ECU를 구성하는 부품이며 ECU 전체와 동일한 개념이 아니다.

### 1.3 기능 범위

| 포함 | 제외 |
|---|---|
| 좌·우 후방 방향지시등, 비상등 | 전방 방향지시등·전조등·DRL |
| 좌·우 공용 미등/제동등 | 조도 기반 AUTO 램프 |
| 후진등, 중앙 보조제동등(CHMSL) | P-R-N-D 전체 변속 상태 모델 |
| CAN 기반 램프 명령, 기본 진단·검증 | 실제 LED 단선·단락 감지회로 및 양산용 전원 설계 |

후방 램프 출력은 TURN_L, TURN_R, TAIL_STOP_L, TAIL_STOP_R, REVERSE_LAMP, CHMSL의 **6개 논리 채널**로 구분한다. 비상등은 별도 출력 채널이 아니라 좌우 방향지시등을 함께 사용하는 기능이다.

## 2. 무엇을 할 수 있어야 하는가?

### 2.1 기능 요구사항

| ID | 기능 | 요구사항 |
|---|---|---|
| STK-001 | 제어 명령 | 후방 ECU는 BCM 시뮬레이터가 네트워크로 보낸 램프 명령을 받아 동작해야 한다. |
| STK-002 | 방향지시 | 좌·우 후방 방향지시등을 개별적으로 제어해야 한다. |
| STK-003 | 비상등 | 비상등 요청 시 양쪽 방향지시등이 동기 점멸하고 일반 방향지시 요청보다 우선해야 한다. |
| STK-004 | 점멸 | 방향지시등·비상등이 일정한 간격으로 점멸하며 동작 전환 시 시작 위상을 일관되게 처리해야 한다. |
| STK-005 | 미등·제동등 | 좌우 공용 출력으로 미등과 제동등을 구현하며 동시 요청 시 제동등을 우선해야 한다. |
| STK-006 | 중앙 제동등 | CHMSL은 제동 요청에만 반응하고 좌우 제동 출력과 별도로 제어할 수 있어야 한다. |
| STK-007 | 후진등 | 후진 요청에 따라 후진등을 켜고 다른 허용된 램프 기능과 동시에 작동해야 한다. |
| STK-008 | 시동 상태 | IGN 상태에 따라 일반 방향지시등·후진등을 제한하고 비상등·미등·제동등은 허용해야 한다. |
| STK-009 | 상태 유지 | 시동 상태 변경 중 비상등 설정을 유지하고 유효한 조작 입력을 재조작 없이 반영해야 한다. |
| STK-010 | 시작 동작 | ECU 초기화 중 출력이 의도치 않게 켜지지 않도록 하고 이후 유효 명령을 반영해야 한다. |
| STK-011 | 비정상 명령 | 모순된 방향지시 요청 등 유효하지 않은 명령을 검출하고 정상 기능에 미치는 영향을 제한해야 한다. |
| STK-012 | 진단 | 시험 중 개별 채널에 가상 고장을 주입·해제하고 오류 이력과 복구 동작을 확인할 수 있어야 한다. |
| STK-013 | CAN 통신 | ECU는 정상 CAN 명령을 처리하고 통신 오류·명령 누락에 대응할 수 있어야 한다. |
| STK-014 | 입력 조작 | BCM 시뮬레이터는 시동·레버·비상등·미등·브레이크·후진 입력을 구별해 전달해야 한다. |
| STK-015 | 전원·동작 | 시동 OFF에서도 허용된 조명 기능이 동작할 수 있어야 한다. |
| STK-016 | 검증 | 소프트웨어 로직과 실제 MCU 출력·통신 동작을 SIL과 HIL에서 재현·검증할 수 있어야 한다. |

### 2.2 조작 입력

| 입력 | 조작 상태 |
|---|---|
| IGN | ON / OFF |
| 방향 레버 | 위=우 / 중앙=OFF / 아래=좌 |
| 비상등 버튼 | 누를 때마다 ON/OFF 토글 |
| 미등 | ON / OFF |
| 브레이크 | 눌림 유지 / 해제 |
| 후진 | R / NOT R 슬라이드 스위치 |

물리 입력의 디바운싱과 비상등 토글은 BCM 시뮬레이터에서 처리한다. ECU는 유효한 CAN 명령을 기준으로 램프를 제어한다.
